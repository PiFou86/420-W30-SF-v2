# Semaine 5 — SOLID, composition et Strategy

| Étape | Activité |
|---|---|
| [Exercice 1](./E01-tell-dont-ask.md) | Confier une décision à l'objet qui possède l'état |
| [Exercice 2](./E02-ocp-lsp-isp.md) | Créer un contrat étroit et réusiner avec OCP, LSP et ISP |
| [Exercice 3](./E03-strategy.md) | Implanter le patron Strategy pour la tarification |
| [Exercice 4](./E04-couches-dto.md) | Classer les responsabilités et protéger la frontière avec un DTO |
| [Exercice 5 — ramassé](./E05-strategy-composition.md) | Réinvestir les principes dans un exercice individuel |

Les exercices 1 à 3 utilisent la même solution .NET cumulative,
[`S05E01E03_Restaurant_Livraison`](./S05E01E03_Restaurant_Livraison/).
L'exercice 4 est une courte activité de conception sur papier ou dans un
fichier Markdown; il ne demande pas un nouveau projet.
L'exercice 5 possède son propre répertoire de solution de départ,
[`S05E05_Restaurant_Rabais`](./S05E05_Restaurant_Rabais/).

Faites l'exercice 4 et son court retour collectif avant de commencer
l'exercice ramassé 5. Celui-ci peut être terminé hors classe selon les
modalités de remise annoncées sur la plateforme d'enseignement.

Dans le dépôt Git de chaque solution, utilisez `dev` comme branche
d’intégration et créez chaque branche `fonctionnalite/...` depuis `dev`, selon
les consignes détaillées dans les énoncés.

Les échéances et les modalités de remise sont indiquées sur la plateforme
d'enseignement.
